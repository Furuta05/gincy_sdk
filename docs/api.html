API Gincy

Не список внутренних функций, а то, чем обычно должен пользоваться модуль. Сначала смотрите ctx.*: контекст автоматически связывает регистрацию с вашим модулем и корректно очищает её при выгрузке.

Готовые модули

Gameplay API
Рекомендация: если операция создаёт долгоживущую регистрацию — hook, timer, route, content type, repository — используйте ctx, когда такая обёртка есть. Именно контекст знает владельца и поколение модуля.
shared

ctx.Hooks:Add(event, id, fn)

ctx.Hooks:Add("PlayerSpawn", "welcome", callback)

Добавляет обычный GMod hook, но формирует уникальное имя из ID модуля и его поколения. При shutdown контекста hook удаляется автоматически.

shared

ctx.Timers:Create(id, delay, repetitions, fn)

ctx.Timers:Create("tick", 1, 0, callback)

Создаёт timer, принадлежащий модулю. delay должен быть не меньше 0.01; repetitions — целое число от 0. Ноль означает повторение без заданного конца.

shared

ctx.Network:Register(id, definition, handler)

ctx.Network:Register("ping", {schema=..., rate=2}, handler)

Регистрирует route как module_id.ping. Требует capability network.register. Definition содержит schema и rate; handler вызывается после проверки сообщения.

shared

ctx.Network:RegisterState(id, schema, onChange)

Регистрирует синхронизируемое состояние модуля. Полный ID автоматически получает префикс модуля. В текущем Core такая регистрация помечает контекст как требующий restart для безопасного изменения структуры.

shared

ctx.Network:RegisterStream(id, handler, options)

Регистрирует канал для больших данных, передаваемых частями. Ownership и cleanup выполняются через контекст.

shared

ctx.Content:RegisterType(kind, schema, policy, schemaVersion)

Создаёт собственный тип контента. Требует content.register. Schema проверяется до регистрации.

shared

ctx.Content:Register(kind, id, definition)

Добавляет запись ранее объявленного типа и связывает её с владельцем-модулем.

ctx.Content:Get / GetAll / Exists

ctx.Content:Get(kind, id) · GetAll(kind) · Exists(kind, id)

Чтение зарегистрированного контента. Возвращаемые таблицы Core копирует там, где это предусмотрено registry API, чтобы внешний код не менял внутреннее состояние напрямую.

server

ctx.Storage:Register(name, schema)

Создаёт repository в namespace module_id.name. Требует persistence.write. Возвращает объект с Get и Set.

server

ctx.Storage:Get / Set

ctx.Storage:Get(key, callback) · ctx.Storage:Set(key, value, callback)

Простой namespace самого модуля. Read требует persistence.read, write — persistence.write. Запись запрещена, пока staged-контекст ещё не активирован.

server

ctx.Storage:Transaction(statements, callback)

Передаёт набор операций storage как транзакцию. Используйте для связанных изменений, которые не должны применяться наполовину.

server

ctx.Console:Register(spec)

Подключает дерево console-команд конкретного модуля к общей команде Gincy. При выгрузке модульная команда удаляется.

ctx.Config:Register(schema)

Создаёт конфигурацию модуля на основе schema. Значения читаются из data/gincy/config/<module>.json, отсутствующие поля получают default.

ctx:GetLogger()

Возвращает простой logger с методами Info, Warn, Error, Debug. Сообщение получает префикс модуля.

ctx:Defer(callback)

Добавляет собственную cleanup-функцию. Полезно, если модуль создаёт ресурс, для которого в Gincy нет готовой обёртки.

ctx:Require(capability)

Проверяет, что capability была заявлена в manifest. При отсутствии права выполнение прерывается с понятной ошибкой.

Gincy.Schema

Gincy.Schema.Validate(spec, value)

Проверяет значение по schema и возвращает нормализованный результат либо описание ошибки. В исходниках поддерживаются object, array, string/reference, enum, boolean, entity, vector, angle, number и целочисленные/varint-представления.

Gincy.Schema.Describe(spec)

Создаёт безопасное описание schema без функций-валидаторов. Удобно для диагностики или UI.

Gincy.Schema.WalkReferences(spec, value)

Находит поля типа reference и возвращает пути и цели ссылок на другой content.

Gincy.Network

Gincy.Network.Request(peer, id, value, callback, timeout)

Отправляет запрос и связывает ответ с callback. Не нужно вручную придумывать отдельный message ID для каждого ответа.

Gincy.Network.SendRoute(...)

Низкоуровневая отправка зарегистрированного route. Для регистрации route внутри модуля предпочтительнее ctx.Network:Register.

Gincy.Network.PublishState(peer, id, value)

Публикует новое значение зарегистрированного replicated state.

Gincy.Network.GetState(id)

Возвращает локальное значение state и его revision.

Gincy.Network.Dictionary / Intern / ResolveIdentifier

Словари позволяют передавать повторяющиеся строковые идентификаторы компактнее. API учитывает revision словаря и умеет запросить resync.

Gincy.Network.SendStream(peer, id, data)

Передаёт большой payload через зарегистрированный stream с ограничениями и учётом состояния передачи.

Gincy.Network.Snapshot()

Возвращает диагностический снимок сетевого слоя: используется management/profiling.

Gincy.Content

Register / Unregister

Базовая регистрация content по паре kind + id с владельцем. В модуле обычно используйте контекстную версию.

Get / GetAll / Exists / Find

Получение записей, проверка существования и простой поиск по kind/id.

Gincy.Modules

Get(id) / GetAll()

Информация о загруженных модулях.

Enable(id, callback)

Включает обнаруженный модуль с проверкой его требований и зависимостей.

Disable(id, cascade)

Отключает модуль. Cascade позволяет учитывать зависящие от него модули.

Reload(id, candidate)

Перезагрузка модуля через lifecycle Gincy вместо ручного повторного include.

Dependents(id)

Возвращает модули, которые зависят от указанного.

Gincy.Permissions

Gincy.Permissions.Has(ply, permission)

Проверяет permission. Core содержит адаптеры для SAM и ULX; если адаптер не дал решения, используется default самой permission.

Gincy.Permissions.RegisterAdapter(id, callback)

Подключает другую систему прав без переписывания кода, который спрашивает Has.

Gincy.Storage

server

Register(namespace, schema, generation)

Низкоуровневая регистрация repository. Для обычного модуля безопаснее ctx.Storage:Register.

Get / Set / Transaction

Асинхронные операции хранения с callback. Реализация использует native database layer.

Diagnostics()

Состояние БД, число pending-запросов и накопленные метрики.

API готовых модулей

Gincy.Characters

Get(ply), List(ply, callback), Create(ply, data, callback), Select(ply, id, callback).

Gincy.Inventory

Create(options, callback), Get(id, callback). Конкретные правила предметов задаются отдельным Items-модулем.

Gincy.Interactions

Start(ply, id, target, data) и Cancel(ply, reason) для зарегистрированных типов взаимодействия.

Gincy.Activities

Create(kind, character, data, callback), Get(id, callback), List(character, callback).

Gincy.Organizations

Create(kind, name, metadata, callback), Get(id, callback).

Gincy.WorldObjects

Create(kind, options, callback), Get(id, callback), GetByEntity(entity).

Gincy.Animation

GetState(ply), SetAction(ply, action, duration) и registry состояний.

Замечание: first-party gameplay API зависит от соответствующего модуля. Это не гарантированная часть минимального Core, если модуль отключён.
