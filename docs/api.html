Это оглавление. На каждой странице разобран один вызов: зачем он на сервере, что писать в скобках, что вернётся и что будет при перезагрузке модуля.

Квадратные скобки в записи синтаксиса значат «этот аргумент можно не писать». В настоящем Lua-коде скобки [ и ] вокруг аргумента писать не нужно.

Гайдыпапки, manifest, команды

  • manifest.lua — Файл, без которого Gincy не загрузит модуль.
  • Файлы модуля — Какие lua-файлы Gincy выполняет и в каком порядке.
  • Файлы контента — Куда класть навык, предмет или тему HUD.
  • dev и production — Где лежит черновик и где лежит то, что видит игровой сервер.
  • От пустой папки до .gmod — Короткий путь, которым модуль попадает на сервер.
  • Сборка .gmod — Команды внешней программы gincy для пакетов.
  • protection — Что значат open, protected и maximum.
  • Перезагрузка — Что снимается при reload модуля и что не трогается при правке контента.
  • Зависимости — Модуль ждёт другой модуль, предмет ждёт другой предмет.
  • Команды gincy на сервере — Что писать в консоли SRCDS. Внешняя программа сборки описана отдельно.

ModuleGincy.Module и методы MOD

  • Gincy.Module — Возвращает объект, через который модуль вешает хуки, время, сеть и контент.
  • MOD:Hook — Вешает обычный игровой хук и снимает его вместе с модулем.
  • MOD:After — Вызывает функцию один раз через несколько секунд.
  • MOD:Every — Повторяет функцию через заданные секунды. Может быть с именем, с настройками и с привязкой к игроку или сущности.
  • MOD:PlayersEvery — Периодически обходит игроков одной задачей, а не таймером на каждого.
  • MOD:Net — Объявляет сетевое сообщение с полями и лимитом.
  • MOD:Receive — Ставит функцию, которая получит уже проверенные данные сообщения.
  • MOD:Send — Отправляет игроку таблицу по уже объявленному сообщению.
  • MOD:Content — Объявляет тип контента: какие поля разрешены у навыка, предмета или темы.
  • MOD:LoadContent — Включает одну запись контента из таблицы, без файла на диске.
  • MOD:Storage — Открывает простое именованное хранилище ключ-значение для модуля.
  • MOD:Unload — Выключает модуль из кода: снимает хуки, задачи, сеть и контент этой загрузки.
  • MOD:Context — Отдаёт объект загрузки, если методов MOD уже не хватает.

Contextобъект ctx одной загрузки

  • ctx:Own — Запоминает, как включить свою вещь и как её потом убрать.
  • ctx:Defer — Кладёт только функцию уборки, без шага включения.
  • ctx:Require — Проверяет, что в manifest модулю выдано нужное разрешение.
  • ctx:Activate — Включает отложенные регистрации, когда модуль уже прошёл подготовку.
  • ctx:Shutdown — Закрывает загрузку и выполняет все уборки.
  • ctx:Hook — То же, что MOD:Hook, если объект у тебя уже ctx.
  • ctx:Timer — Повторяющаяся задача с именем, интервалом и числом повторов. Для обычного кода есть MOD:Every.
  • ctx:GetLogger — Возвращает четыре функции печати с именем модуля в строке.
  • Register, Get, Exists — Общий способ записать команду, право или сетевой канал за модулем.
  • ctx.Network:RegisterState — Объявляет таблицу состояния, которую сервер может рассылать игрокам по изменениям.
  • ctx.Network:RegisterStream — Объявляет передачу большого куска данных кусками, не одним пакетом.
  • ctx.Console:Register — Добавляет подкоманды модуля в консоль gincy.
  • ctx.Config.Register — Собирает числа и строки настроек модуля из кода и из json на диске.
  • ctx.Storage:Get, Set, Register, Transaction — Прямой доступ к базе, если не хватает MOD:Storage.

Schedulerзадачи по времени

  • Gincy.Scheduler.Schedule — Ставит задачу в общий планировщик. Обычный код вызывает MOD:Every и MOD:After, они зовут эту функцию сами.
  • Gincy.Scheduler.Cancel — Снимает задачу по id, по владельцу, по контенту или по сущности.
  • Gincy.Scheduler.Inspect и Snapshot — Показывает одну задачу или сводку по всем. В игре то же делает консоль.
  • Gincy.Scheduler.Configure — Меняет, сколько миллисекунд за тик можно отдать обычным задачам.

Contentнавыки, предметы, файлы

  • Gincy.Content.RegisterType — Объявляет тип контента без обёртки MOD:Content. Обычному модулю хватает MOD:Content.
  • Gincy.Content.Activate — Проверяет одну запись и делает её активной, не трогая модуль.
  • Gincy.Content.Call — Вызывает функцию, которую вернул файл контента, и передаёт ей безопасный объект записи.
  • Get, Exists, GetAll, Find — Читает уже принятые записи. Не читает файл с диска заново.
  • Reload, Stage, Apply, Rollback — Подменяет несколько записей сразу или возвращает предыдущую таблицу.
  • Gincy.Content.Validate — Проверяет таблицу по типу и ничего не включает.
  • Gincy.Content.MigrateType — Учит тип читать старые таблицы, когда у схемы появилось новое поле.

Schemaописание и проверка полей

  • Gincy.Schema.Check — Проверяет, что описание полей само написано без ошибок.
  • Gincy.Schema.Validate — Проверяет таблицу игрока или файл по схеме и возвращает нормальную копию.

Networkсообщения клиент и сервер

  • Gincy.Network.Register — Регистрирует канал напрямую. MOD:Net делает это с готовыми rate и direction.
  • Gincy.Network.Send — Ставит в очередь уже зарегистрированный канал.
  • Gincy.Network.Request — Отправляет сообщение и ждёт один ответ по схеме response.
  • RegisterState, PublishState, GetState — Хранит таблицу и рассылает её изменения. Для объявления из модуля есть ctx.Network:RegisterState.
  • RegisterStream, SendStream — Передаёт длинные данные кусками. Объявление из модуля — ctx.Network:RegisterStream.

Storageзаписи в базе

  • Gincy.Storage.Get и Set — Читает и пишет одно значение по полному имени пространства и ключу.
  • Gincy.Storage.Diagnostics — Возвращает состояние базы без пароля.

Permissionsпроверка игрока

  • Gincy.Permissions.Has — Спрашивает, можно ли игроку выполнить действие.

Configчисла и строки модуля

  • Gincy.Config.Register — То же, что ctx.Config.Register, но id файла задаёшь сам.

Modulesсписок, enable, disable, reload

  • Gincy.Modules.Get и GetAll — Показывает, в каком состоянии модуль, не загружая его заново.
  • Gincy.Modules.Enable, Disable, Reload — Включает, выключает или перечитывает модуль. Те же действия, что у команд gincy module.

Gincy.APIсравнение версий

  • Gincy.API.IsCompatible — Проверяет, попадает ли версия в диапазон из manifest.
