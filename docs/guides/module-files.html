Модуль в разработке — это папка garrysmod/gincy_dev/modules/имя/. В корне лежит manifest.lua. Рядом лежат lua-файлы. Имя файла говорит, где его выполнять: sv_ только на сервере, cl_ только на клиенте, sh_ и там и там.

Зачем это нужно. Так ты не тащишь серверный расчёт урона на клиент и не забываешь общий код. Загрузчик сам отбрасывает чужую сторону: сервер не выполняет cl_, клиент не выполняет sv_.

Где это встречается на сервере

  • Общая регистрация навыка в sh_init.lua и серверный удар в sv_init.lua.
  • Клиентский HUD в cl_init.lua, который только рисует числа.

Синтаксис

gincy_dev/modules/stamina/
    manifest.lua
    sh_init.lua
    sv_init.lua
    cl_hud.lua

Порядок задаёт entrypoints. Если список пуст, файлы идут по алфавиту, кроме самого manifest.lua: его как код не выполняют.

Что означает каждая часть

  • sv_ — Файл выполняется только когда это сервер. realm в пакете равен 1.
  • sh_ — Файл выполняется и на сервере, и на клиенте. realm равен 2.
  • cl_ — Файл выполняется только на клиенте. realm равен 3.
  • migrations/*.sql — Это не Lua. Загрузчик помечает такие файлы как миграции базы модуля.

Что возвращается

Страница описывает раскладку. Сами файлы ничего не возвращают, пока ты не напишешь в них return.

Что происходит после вызова

При загрузке каждый подходящий файл компилируется и выполняется. Внутри него уже есть глобальный Gincy. В файле обычного модуля вызывай Gincy.Module с id из manifest. Если файл выполняется внутри загрузки другого id, вызов с чужим именем завершится ошибкой: модуль привязан к текущему id.

Перезагрузка и выгрузка

Старые хуки и задачи снимаются вместе с модулем, даже если они были созданы из sv_init.lua. Файл на диске при перезагрузке читается заново. Уже выданный .gmod сам с диска разработки не обновляется, пока ты его не пересоберёшь.

Ограничения

  • Файл без префикса sv_, sh_ или cl_ в обход папки загрузчик в список кода не кладёт.
  • manifest.lua в список выполнения не входит.
  • Вложенные папки обходятся, префикс смотрится у имени файла, не у папки.

Рядом обычно вызывают

  • manifest.lua — Поле entrypoints.
  • Сборка — Как папка становится .gmod.

Сервер и клиент

entrypoints = { "sh_init.lua", "sv_init.lua", "cl_hud.lua" }

Сначала общий код объявит MOD и тип контента. Потом сервер повесит урон. Клиент выполнит только cl_hud.lua и не увидит серверный файл.
