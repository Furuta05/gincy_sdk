Сначала папка в gincy_dev/modules, потом проверка на своём сервере, потом одна команда сборки. Контент в .gmod не зашивается: навыки остаются в gincy_content.

Зачем это нужно. Так ты не копируешь DLL руками и не путаешь код системы с таблицей урона.

Где это встречается на сервере

  • Первый модуль stamina.
  • Боевая система, к которой каждую неделю добавляют навык.

Синтаксис

gincy create module stamina
-- правка sh_init.lua
-- проверка в игре
gincy package build garrysmod/gincy_dev/modules/stamina --key signer.pem

Последняя команда — это отдельная программа gincy, не консольная команда карты. Она читает папку и пишет garrysmod/gincy_modules/stamina.gmod. Исходная папка не изменяется.

Что означает каждая часть

  • create module — Создаёт manifest.lua и пустой sh_init.lua.
  • правка — Обычный GLua через MOD:...
  • package build — Подпись ключом и файл .gmod. Без --output путь назначения — gincy_modules/id.gmod.
  • контент — Отдельная команда gincy create content combat skill fireball, когда тип combat.skill уже объявлен запущенным модулем.

Что возвращается

Команды создают файлы. Игровая логика от них сама не запускается, пока сервер не загрузит модуль.

Что происходит после вызова

create module откажется, если id не подходит под правило строчных букв. package build откажется без ключа подписи. Успешная сборка не удаляет папку разработки.

Перезагрузка и выгрузка

Пересборка .gmod нужна, когда меняется код модуля. Новый файл навыка пересборки не требует.

Ограничения

  • Ключ signer.pem — секрет подписи. Его не кладут в репозиторий и не в пакет.
  • Внутриигровой gincy package build только печатает, что собирать надо внешней программой.

Рядом обычно вызывают

  • Сборка — Флаги команды.
  • protection — open, protected и maximum.

Неделя навыков

Неделя 1: файл fireball.lua в gincy_content/combat/skill.
Неделя 2: dash.lua и uppercut.lua.
Неделя 3: в fireball.lua damage меняется с 50 на 45, добавляется lightning.lua.

Combat.gmod эти три недели не пересобирается. Модуль остаётся загруженным. Меняются только файлы контента. Если в неделе 3 написать cooldown = "fast", старый фаербол с числом останется активным.
