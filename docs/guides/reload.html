У загрузки модуля есть номер. Хуки, задачи и регистрации помечаются этим номером. Shutdown идёт по списку уборок с конца: hook.Remove, отмена задач этого номера, снятие сетевых обработчиков того же номера.

Зачем это нужно. Можно выложить новый sh_init.lua и не оставить на сервере два регена выносливости сразу.

Где это встречается на сервере

  • Ты поменял формулу регена и пишешь gincy module reload stamina.
  • Ты поменял damage в fireball.lua и модуль трогать не хочешь.

Синтаксис

gincy module reload stamina
gincy dev reload stamina

Обе команды просят перезагрузку. Горячей она будет только при reload = MODULE_HOT_SWAP и если модуль не встроенный. Иначе ответ RESTART_REQUIRED.

правка gincy_content/.../fireball.lua

Модуль не перезагружается. Обход контента готовит новую таблицу и подменяет запись, только если проверка прошла.

Что означает каждая часть

  • MODULE_HOT_SWAP — Единственная строка в manifest, которая разрешает горячую перезагрузку.
  • неудачный новый код — Если новый файл модуля падает при выполнении, загрузчик возвращает прежний активный модуль и ставит состояние с ошибкой GINCY-MOD-INITIALIZE.
  • неудачный контент — Новая таблица отвергается, предыдущая запись остаётся, модуль остаётся ACTIVE.

Что возвращается

Команда возвращает успех или код ошибки. Игрокам сама по себе ничего не шлёт.

Что происходит после вызова

Перед новым кодом вызывается уборка старой загрузки. Потом выполняются entrypoints заново.

Перезагрузка и выгрузка

Контент, принадлежащий модулю, при полной уборке модуля тоже отпускается: его задачи отменяются. Правка одного файла контента остальные навыки не выгружает.

Ограничения

  • Встроенный модуль ядра горячо не перезагружается.
  • Два MOD:Hook на одно и то же событие без своего id делят одно внутреннее имя хука и второй вызов заменяет функцию первого.

Рядом обычно вызывают

  • MOD:Unload — Снять модуль из кода.
  • ctx:Own — Если уборка нужна для своей вещи.

Реген

Было MOD:Every("regen", 1, стараяФункция).
После reload в файле уже новая функция.
Старая больше не вызывается: задача была помечена номером прошлой загрузки и отменена.

Игроки не получают два прибавления стамины за тик.
