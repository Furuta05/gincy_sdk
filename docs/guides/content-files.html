Контент — обычные .lua или .json файлы, не новый формат пакета. Их две папки: garrysmod/gincy_content/ для production и garrysmod/gincy_dev/content/ для dev. Вторая читается только если в data/gincy/runtime.json поле development равно true.

Зачем это нужно. Урон фаербола меняется чаще, чем код боевой системы. Файл контента можно заменить, не трогая Combat.gmod.

Где это встречается на сервере

  • Новый навык lightning.lua.
  • Предмет ak74, который ссылается на патроны.
  • Тема HUD, где можно менять только разрешённые поля.

Синтаксис

gincy_content/combat/skill/fireball.lua

return {
    name = "Fireball",
    damage = 50,
    cooldown = 4
}

Папка combat — модуль-владелец. Папка skill — короткая часть типа. Вместе это тип combat.skill, запись fireball. Так файлы читает DiscoverContent.

gincy_content/skill/fireball.lua

-- старый плоский вид: тип равен имени папки skill, id равен fireball

Если внутри папки нет подпапок, тип — это имя первой папки, без точки. Такой вид загрузчик тоже принимает.

Что означает каждая часть

  • модуль/тип/id.lua — Вложенный вид. Тип получается module.type, id — имя файла без .lua или .json.
  • тип/id.lua — Плоский вид. Тип — имя папки.
  • depends — Необязательный список строк вида тип/id, если такого поля нет в схеме. Пример: inventory.item/ammo_545. Пока цели нет, запись не станет активной.
  • uses — Список имён возможностей, которые файл хочет звать. Модуль должен был их открыть в MOD:Content. Иначе запись отклоняется.
  • функции в таблице — Их можно вернуть, например cast = function(skill) ... end. В проверку полей они не входят. Вызвать их может модуль через Gincy.Content.Call.

Что возвращается

Файл возвращает таблицу. Её не кладут в глобальную переменную вручную: Gincy сам читает файл.

Что происходит после вызова

Сначала разбирается текст. Lua выполняется в пустой среде: нет _G и нет Gincy, поэтому файл не может тихо прочитать внутренние таблицы модуля. Потом проверяются поля, зависимости и возможности. Если всё сошлось, запись становится активной. Если уже была старая и новая сломана, старая остаётся.

Перезагрузка и выгрузка

Смена файла не перезагружает модуль. При успехе старые задачи этого конкретного навыка отменяются. При ошибке прежняя версия и её задачи не трогаются.

Ограничения

  • Два файла с одним id: если файл из gincy_dev уже загружен, такой же файл из gincy_content пропускается. В диагностике это development override, двойной загрузки нет.
  • JSON тоже принимается. Для поведения с функциями нужен .lua.
  • id в имени файла должен подходить под правило идентификатора: строчные буквы, цифры, _, точка и двоеточие, не длиннее 96.

Рядом обычно вызывают

  • MOD:Content — Как модуль объявляет поля.
  • dev и production — Какая папка перекрывает другую.

Фаербол

return {
    name = "Fireball",
    damage = 50,
    cooldown = 4,
    cast = function(skill)
        skill:After(2, function()
            -- взрыв через 2 секунды, если модуль открыл After
        end)
    end
}

name, damage и cooldown проверяются схемой. cast — функция, в схему не входит. skill:After появится только если модуль в возможностях типа указал Schedule или After. Иначе вызов метода у навыка будет пустым.
