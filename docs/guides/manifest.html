manifest.lua — это обычный Lua-файл в корне модуля. Он не содержит игровой логики. Он возвращает таблицу: как модуль называется, какую версию Gincy он ждёт и какие файлы выполнять.

Зачем это нужно. Загрузчик читает эту таблицу до любого твоего кода. Если id кривой или версия Gincy не попадает в указанный диапазон, модуль даже не стартует. Поля, которых нет в коде загрузчика, ни на что не влияют: их можно не придумывать.

Где это встречается на сервере

  • Сервер поднимает папку из gincy_dev/modules.
  • Сервер ставит готовый stamina.gmod из gincy_modules.
  • Ты хочешь горячую перезагрузку командой gincy module reload.

Синтаксис

return {
    id = "stamina",
    name = "Stamina",
    author = "local",
    version = "1.0.0",
    requires = {
        gincy = ">=3.2.0 <4.0.0",
        api = ">=1.1.0 <2.0.0"
    },
    dependencies = {},
    capabilities = {"content.register", "network.register"},
    reload = "MODULE_HOT_SWAP",
    entrypoints = {"sh_init.lua"}
}

Так выглядит шаблон, который пишет gincy create module. Ниже — только те поля, которые код действительно читает.

Что означает каждая часть

  • return { ... } — Файл должен вернуть таблицу. Это не JSON.

Аргументы

АргументТипОбязательныйПо умолчаниюЧто передавать
idстрокаданетКороткое имя латиницей: первая буква, дальше буквы, цифры и _. Не длиннее 48 символов. По нему зовут Gincy.Module("id") и папку. Если формат другой, загрузка останавливается с ошибкой invalid module id.
versionстрока x.y.zданетВерсия самого модуля, три числа через точку, без нуля в начале вроде 01. Загрузчик проверяет, что строка похожа на версию. Если поле пустое или это 1.0, модуль не загрузится.
requires.gincyстрока диапазонада в новом виденетКакой продукт Gincy подходит. Пример: >=3.2.0 <4.0.0. Сравнивается с полем product из version.json, сейчас 3.3.0. Несколько условий пишутся через пробел, должны выполниться все.
requires.apiстрока диапазонада в новом виденетКакая версия программного интерфейса подходит. Сейчас каркас сообщает 1.1.0. Модуль с api >=1.1.0 <2.0.0 на 3.3.0 загружается.
gincyстрокатолько старый виднетЕсли нет таблицы requires с обеими строками gincy и api, загрузчик считает манифест старым и берёт это поле как диапазон api, а продукт считает совместимым с >=3.0.0 <4.0.0. В списке модулей такой источник помечается legacy.
dependenciesтаблицанет{}Другие модули, без которых этот не стартует. Ключ — id модуля, значение — диапазон его version. Пустая таблица значит «ни от кого не завишу». Если зависимого модуля нет или его версия не подходит, этот модуль получает состояние FAILED и текст missing/incompatible dependency.
capabilitiesсписок строкнетпустой списокРазрешения, которые код модуля потом проверит через ctx:Require. Примеры из кода: content.register, network.register, persistence.read, persistence.write, commands.register. Если в gincy/runtime.json задан allowedCapabilities и строки там нет, модуль не попадёт в список. Отсутствие поля не запрещает загрузку, но ctx:Require на неизвестное разрешение упадёт.
entrypointsсписок имён файловнетвсе подходящие файлы по алфавитуКакие lua-файлы выполнить и в каком порядке. Имена должны лежать в модуле. Префикс sv_ — только сервер, cl_ — только клиент, sh_ — оба. Файл migrations/*.sql помечается как миграция базы, а не как Lua. Если список пуст, берутся все такие файлы, отсортированные по имени.
reloadстроканетнет горячей перезагрузкиЕдинственное значение, которое включает горячую перезагрузку: MODULE_HOT_SWAP. Любое другое или отсутствие поля: gincy module reload вернёт ошибку RESTART_REQUIRED. Встроенный модуль ядра так тоже не перезагружается.
nameстроканетзагрузчик не требуетЧеловеческое название. Шаблон его пишет, список gincy modules показывает id и version, не name. Если поля нет, модуль всё равно загрузится.
authorстроканетзагрузчик не требуетПодпись автора. Особый случай только один: author равен Gincy, тогда в списке модулей источник рисуется как builtin, а не dev. Для своего аддона ставь своё имя или local, как в шаблоне.
required_gincyдиапазон или числонетпроверка пропускаетсяДополнительная проверка уже собранного пакета, не обычного manifest.lua в папке. Если поле есть и сервер не попадает в диапазон, пакет отвергается.
required_framework_apiдиапазон или числонетпроверка пропускаетсяТо же для версии API пакета.
required_native_abiчислонетпроверка пропускаетсяДолжно совпасть с native_abi рантайма. Сейчас это 2. Иначе пакет не ставится: нужна другая DLL.
required_network_protocolчислонетпроверка пропускаетсяДолжно совпасть с протоколом сети. Сейчас 2.
package_formatчислонетпроверка пропускаетсяДолжно быть равно формату пакета рантайма. Сейчас 2.
protectionстроканетдля показаПоле читает осмотр пакета. Режимы сборки задаются флагами CLI, см. страницу защиты. Само по себе слово в manifest.lua файлы не шифрует.
protection_policyтаблицанетopenВнутри собранного пакета. Поля server и client: open, protected или maximum. Это уже результат сборки, не то, что ты пишешь руками в шаблоне.
allow_unpackлогическоенетраспаковка не запрещена подписьюЕсли в подписанной политике запрещена распаковка, официальная команда unpack откажется вытаскивать закрытые файлы.
drmtrue или таблицанетвыключеноЕсли drm равен true или drm.enabled равен true, сервер ищет аренду в data/gincy/trust/leases/id.json. Без неё закрытый пакет с этим флагом не принимается.

Что возвращается

Файл ничего не возвращает в игровой код. Загрузчик получает таблицу и либо принимает модуль, либо останавливает загрузку ошибкой.

Что происходит после вызова

Дальше Gincy ищет файлы из entrypoints, создаёт объект загрузки и выполняет их. Твой sh_init.lua в этот момент уже может вызвать Gincy.Module с тем же id.

Перезагрузка и выгрузка

Смена manifest.lua — это смена модуля, а не контента. Горячая перезагрузка подхватит новый manifest только если reload равен MODULE_HOT_SWAP и команда reload прошла. Сломанный manifest оставляет модуль в FAILED, старый активный код при неудачной перезагрузке возвращается.

Ограничения

  • id не может содержать точку, дефис и заглавные буквы.
  • version — ровно три числа.
  • Диапазон requires пишется как >=1.2.3, <=1.2.3, >1.2.3, <1.2.3 или =1.2.3. Несколько условий через пробел.
  • Поля вроде description, license, realm загрузчик не читает. Писать их можно, на загрузку они не влияют.

Рядом обычно вызывают

  • Файлы модуля — Куда класть sv_ и sh_.
  • Gincy.Module — Первая строка в sh_init.lua.
  • От папки до .gmod — Полный путь сборки.

Рабочий stamina

return {
    id = "stamina",
    name = "Stamina",
    author = "server",
    version = "1.0.0",
    requires = { gincy = ">=3.2.0 <4.0.0", api = ">=1.1.0 <2.0.0" },
    dependencies = {},
    capabilities = { "network.register", "content.register", "persistence.read", "persistence.write" },
    reload = "MODULE_HOT_SWAP",
    entrypoints = { "sh_init.lua", "sv_init.lua" }
}

Сервер 3.3.0 подходит под >=3.2.0 и <4.0.0. Сначала выполнится общий файл, потом серверный. Горячая перезагрузка разрешена. Разрешения покрывают сеть, контент и базу: без persistence.read вызов чтения из базы внутри ctx упадёт.

Модуль, которому нужен инвентарь

dependencies = {
    inventory = ">=1.0.0 <2.0.0"
}

Пока модуль inventory не загружен или его version ниже 1.0.0, этот модуль не включится. В gincy modules у него будет FAILED.
