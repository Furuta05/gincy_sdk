Модули dev: garrysmod/gincy_dev/modules. Контент dev: garrysmod/gincy_dev/content. Модули production: garrysmod/gincy_modules/*.gmod. Контент production, который можно править на сервере: garrysmod/gincy_content. Служебные файлы Gincy, включая runtime.json и database.json, лежат в garrysmod/data/gincy.

Зачем это нужно. Чтобы править навык на живом сервере, не нужно класть туда исходники Combat. Папка dev не подменяет production сама: её включает поле development.

Где это встречается на сервере

  • Ты пишешь модуль у себя и ещё не собирал .gmod.
  • На сервере админ добавил lightning.lua в gincy_content.
  • Один и тот же nova есть и в gincy_content, и в gincy_dev/content.

Синтаксис

gincy/runtime.json
{
    "development": true,
    "watch": false,
    "enabled": { "stamina": true }
}

Файл создаётся сам при первом запуске, development по умолчанию false. Пока false, папка gincy_dev/content не читается. Пакеты из gincy_modules читаются в обоих режимах.

Что означает каждая часть

  • development — true включает чтение gincy_dev/content. false — нет.
  • enabled — Таблица id модулей, которые разрешено включить. При старте модуль помечается выключенным, если его id нет в enabled со значением true.
  • dev override — Если запись уже пришла из gincy_dev, такой же id из gincy_content пропускается. В таблице Overrides остаётся, какой файл production перекрыт.

Что возвращается

Это описание папок, не функция.

Что происходит после вызова

При старте создаются gincy_modules, gincy_content, gincy_dev/modules, gincy_dev/content и data/gincy с подпапками. Контент сначала читается из gincy_content, потом из gincy_dev, если development включён. Уже занятый id из dev повторно не грузится.

Перезагрузка и выгрузка

Выключение development не удаляет файлы. Оно только перестаёт их читать на следующем обходе контента.

Ограничения

  • gincy create module пишет только в gincy_dev/modules.
  • gincy create content пишет только в gincy_dev/content.
  • Пароль базы лежит в data/gincy/database.json и в документацию, логи и JSON-вывод команд не копируется.

Рядом обычно вызывают

  • Файлы контента — Имена папок.
  • Команды — gincy dev on и create.

Перекрытие

production: gincy_content/combat/skill/nova.lua с damage = 50.
dev: gincy_dev/content/combat/skill/nova.lua с damage = 12.

При development = true активен файл dev, урон 12. Файл production не загружается второй копией. В диагностике видно оба пути.
