Зависимости модулей пишутся в manifest.lua. Зависимости контента пишутся в самом файле: список depends или поле-ссылка в схеме. И то и другое проверяется до включения.

Зачем это нужно. Автомат не должен включаться, если на сервере нет патрона, на который он ссылается.

Где это встречается на сервере

  • inventory зависит от ничего, ak74 зависит от ammo_545.
  • Работа зависит от модуля jobs версии не ниже 1.2.0.

Синтаксис

dependencies = { inventory = ">=1.0.0 <2.0.0" }

-- внутри предмета
return {
    name = "AK-74",
    depends = { "inventory.item/ammo_545" }
}

Строка зависимости контента — это тип, слэш, id. Не путь к файлу.

Что означает каждая часть

  • dependencies модуля — Ключ — id другого модуля, значение — диапазон версий, как в requires.
  • depends — Список. Кривая строка даёт GINCY-CONTENT-DEPENDENCY и текст invalid dependency.
  • ссылка в схеме — Поле типа reference. Проверка смотрит, что такая запись контента уже есть, если у поля не указаны optional или allowMissing.

Что возвращается

Нет отдельного возвращаемого значения: модуль либо доходит до ACTIVE, либо остаётся FAILED. Контент либо активируется, либо остаётся в списке ошибок.

Что происходит после вызова

Граф модулей обходится при старте. Контент проверяет зависимости прямо перед активацией, вместе с текущей пачкой файлов, чтобы два новых файла могли сослаться друг на друга в одном обходе.

Перезагрузка и выгрузка

Выгрузка модуля, от которого зависят другие, через gincy module disable без флага не обязана снести зависимых первой. Флаг cascade сначала выключает тех, кто от него зависит.

Ограничения

  • Цикл «A ждёт B, B ждёт A» загрузчик модулей не считает успешным порядком.
  • Ссылка контента на самого себя в depends пропускается и ошибкой не считается.

Рядом обычно вызывают

  • manifest — Поле dependencies.
  • Активация контента — Когда ссылка блокирует запись.

Патроны

Пока нет inventory.item/ammo_545, файл ak74 не становится активным.
После появления патрона следующий успешный обход может включить автомат.
Модуль инвентаря при этом не перезагружается.

Игрок не видит предмет с дырявой ссылкой.
