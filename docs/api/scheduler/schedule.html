Планировщик один на сервер. У задачи есть владелец — обычно id модуля. По времени следующего запуска задачи лежат так, чтобы тик не просматривал все сотни задач, а брал только уже подошедшие.

Зачем это нужно. Свой повтор, который не укладывается в формы MOD:Every. Задача от имени контента, если ты пишешь сам тип, а не файл навыка.

Где это встречается на сервере

  • Уборка с классом maintenance.
  • Одноразовый удар с задержкой.

Синтаксис

local id = Gincy.Scheduler.Schedule({
    owner = "stamina",
    name = "cleanup",
    interval = 30,
    precision = "relaxed",
    class = "maintenance",
    fn = function()
        print("уборка")
    end
})

Таблица, не пачка отдельных аргументов. owner и fn обязательны.

Что означает каждая часть

  • owner — Строка, кто отвечает за задачу. Для модуля это его id.
  • fn — Функция. Если задана entity, ей передадут эту сущность. Иначе вызов без аргументов.
  • interval — Секунды повтора. Без interval и без бесконечных reps задача одноразовая.
  • delay — Сдвиг первого запуска. Для After используется он, reps равен 1.
  • name — Если задано, новая задача с тем же owner и name отменяет старую.
  • reps — Сколько раз выполнить. По умолчанию 0, а 0 в этом планировщике значит «не ограничивать число», пока есть interval. Для одного раза передай 1.
  • precision — exact, normal или relaxed. По умолчанию normal. relaxed чуть сдвигает срок, не больше 10 процентов интервала.
  • class — gameplay, normal или maintenance. По умолчанию normal. gameplay и precision exact не откладываются из-за бюджета кадра.
  • mode — rate или delay. По умолчанию rate: после фриза будет один вызов, пропуски посчитаются в missed, а не сто вызовов подряд. delay считает следующий срок от текущего момента.
  • entity — Игрок или энтити. Невалидный объект отменяет задачу.
  • kind — Строка players включает обход игроков, как PlayersEvery.
  • spread и batch — Нарезка обхода. batch по умолчанию 20.
  • content — Строка тип/id, если задача принадлежит записи контента.

Что возвращается

Строка id задачи вида владелец:номер.

Что происходит после вызова

Задача кладётся в расписание. Движок тикает планировщик сам. Ошибка функции не роняет остальные задачи. Восемь ошибок подряд выключают именно её, в консоль пишется disabled.

Перезагрузка и выгрузка

CancelOwner с id модуля и номером загрузки снимает задачи этой загрузки. Без номера снялись бы все задачи владельца. Выгрузка модуля передаёт номер.

Ограничения

  • Бюджет кадра по умолчанию 0,002 секунды на обычные и relaxed задачи. Меняется Configure.
  • SetNow, Measure, Tick, Benchmark и CountOwner тоже лежат в таблице планировщика. Это служебные входы для тестов и тика. Из аддона их не вызывают: SetNow ломает часы, Tick дергает ядро само.
  • Не создавай timer.Create рядом «для надёжности».

Рядом обычно вызывают

  • MOD:Every — Нормальный вызов.
  • Cancel — Снять раньше времени.

Уборка

Gincy.Scheduler.Schedule({
    owner = MOD:Context().ID,
    moduleGeneration = MOD:Context().generation,
    name = "cleanup",
    interval = 30,
    precision = "relaxed",
    class = "maintenance",
    source = "module scheduler",
    fn = function()
        print("чистим кэш")
    end
})

Раз в 30 секунд печать. Если кадр занят тяжёлым gameplay, эту задачу можно отложить. Взрыв через MOD:After не отложится: у него класс gameplay. При reload номер загрузки другой, эта задача снимется.
