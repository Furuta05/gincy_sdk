Подменяет несколько записей сразу или возвращает предыдущую таблицу.

Зачем это нужно. Stage только проверяет пачку и ничего не публикует. Apply публикует уже проверенное и помнит до 10 прошлых копий. Reload — это Stage и сразу Apply. Rollback достаёт последнюю копию. Обычная правка файла идёт через Activate, который внутри зовёт Reload для уже существующей записи.

Где это встречается на сервере

  • Выложить десять предметов одной пачкой.
  • Откатить предмет командой gincy content rollback.

Синтаксис

local ok, err = Gincy.Content.Reload({
    { kind = "inventory.item", id = "bread", definition = { name = "Bread", price = 5 } }
}, "inventory")
Gincy.Content.Rollback("inventory.item", "bread", "inventory")

definition — уже поля без функций, тип должен быть зарегистрирован.

Что означает каждая часть

  • entries — Список до 4096 таблиц с kind, id, definition.
  • owner — Кто пишет. Чужая существующая запись даёт NOT_OWNER и вся пачка не применяется.
  • Rollback — Снимает одну ступень истории. Если истории нет — NO_REVISION.

Аргументы

АргументТипОбязательныйПо умолчаниюЧто передавать
entriesсписокданетПустой список применяет ноль записей и это успех.
ownerстрокаданетid модуля-владельца.

Что возвращается

true и число записей, либо false и ошибка. При ошибке проверки живые записи не меняются. Rollback возвращает true или false и ошибку.

Что происходит после вызова

История пишется до подмены. Версия записи увеличивается. Диск gincy_content сам не переписывается: это память процесса.

Перезагрузка и выгрузка

Выгрузка модуля чистит записи владельца через Cleanup. История при этом не обязана остаться полезной: записи уже сняты.

Ограничения

  • Rollback не читает файл заново. Он возвращает прошлую таблицу из памяти, их не больше десяти.
  • Stage один не меняет игру. Пока нет Apply, игроки видят старое.

Рядом обычно вызывают

  • Activate — Путь одного файла.
  • content rollback — Та же операция из консоли.

Цена хлеба

local ok, err = Gincy.Content.Reload({
    { kind = "inventory.item", id = "bread", definition = { name = "Bread", price = 5 } }
}, "inventory")
if not ok then print(err.message) end

Если у предмета price должен быть числом и ты передал 5, запись обновится, модуль инвентаря не перезагрузится. Если передал строку, ok будет false, в магазине останется прежняя цена.
