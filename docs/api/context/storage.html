Прямой доступ к базе, если не хватает MOD:Storage.

Зачем это нужно. MOD:Storage("players") уже вызывает Register с пустой схемой. Прямые методы нужны, когда ключи лежат в пространстве самого модуля или когда нужна пачка SQL.

Где это встречается на сервере

  • Прочитать ключ без отдельного имени хранилища.
  • Несколько записей одним транзакционным списком.

Синтаксис

ctx.Storage:Get("profile", function(ok, err, value)
    print(ok, value)
end)

Ключ в пространстве id модуля. Нужно persistence.read.

ctx.Storage:Set("profile", { stamina = 40 }, function(ok, err, value) end)

Нужно persistence.write. Пока загрузка не активна, Set запрещён.

local repo = ctx.Storage:Register("players", { stamina = "number" })
repo:Set("76561190000000000", { stamina = 40 }, function() end)

Схема полей: если она не пустая, значение обязано быть таблицей и типы полей должны совпасть. Иначе callback получит INVALID_VALUE.

ctx.Storage:Transaction({
    { sql = "SELECT 1", params = {} }
}, function(ok, err, value) end)

Список запросов. Это уже прямой SQL. Пиши его только если Get/Set не выражают задачу. Нужна активная загрузка и persistence.write.

Что означает каждая часть

  • key — Идентификатор до 96 символов.
  • value — То, что уйдёт в JSON. Размер текста не больше 16384.
  • callback — ok, ошибка, значение. Вызывается позже. Если к этому моменту ctx закрыт, callback хранилища не зовут.
  • схема Register — Таблица поле = имя lua-типа строкой, не полная схема контента.

Аргументы

АргументТипОбязательныйПо умолчаниюЧто передавать
keyстрокада для Get/SetнетНе SteamID с пробелами: только правило идентификатора. SteamID64 подходит.
valueлюбое кодируемоеда для SetнетПри пустой схеме тип свободный. При непустой — таблица полей.
callbackfunctionда для Getнет для SetSet можно звать без функции, результат тогда некому отдать.
statementsсписок таблицда для TransactionнетКаждая таблица с sql и params.

Что возвращается

Get и Set ничего не возвращают в момент вызова. Результат только в callback. Register возвращает объект с собственными Get и Set. Transaction возвращает то, что вернёт слой базы.

Что происходит после вызова

Запрос уходит в очередь PostgreSQL. Кадр сервера не ждёт ответ. Ошибка соединения приходит как неуспех callback, пароль в текст не кладётся.

Перезагрузка и выгрузка

Unregister снимает схему этого номера. Сами строки gincy_storage остаются, пока ты их не перепишешь отдельным запросом.

Ограничения

  • Без настроенной базы callback не получит данные. Сначала gincy storage setup.
  • Transaction не проверяет поля контента. Ошибочный SQL вернётся ошибкой базы.
  • Get на клиенте не имеет смысла: файл базы серверный.

Рядом обычно вызывают

  • MOD:Storage — Короткая форма.
  • Состояния базы — READY и ошибки входа.

Профиль

ctx.Storage:Set("profile", { stamina = ply:GetNWInt("Stamina", 0) }, function(ok, err)
    if not ok then print(err.code) end
end)

Ключ profile лежит в пространстве модуля, полное имя для SQL — id модуля. Ответ придёт позже. Если код INVALID_VALUE, значение не прошло схему или размер. Если базы нет, код будет про соединение, не про игрока.
