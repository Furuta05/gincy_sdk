Собирает числа и строки настроек модуля из кода и из json на диске.

Зачем это нужно. В коде ты задаёшь тип, значение по умолчанию и при желании минимум с максимумом. Если в data/gincy/config/idМодуля.json есть то же поле, берётся оно. Игроки этот json не присылают.

Где это встречается на сервере

  • Максимальная стамина сервера.
  • Включить или выключить реген без правки кода.

Синтаксис

local cfg = ctx.Config.Register({
    max = { type = "number", default = 100, min = 1, max = 500 },
    enabled = { type = "boolean", default = true }
})
print(cfg.max)

Ключ таблицы — имя настройки. type — lua-тип: number, string или boolean.

Что означает каждая часть

  • type — Строка типа Lua, сравнивается через type(value).
  • default — Обязателен по смыслу, если в json поля нет: иначе значение nil и проверка типа упадёт.
  • min и max — Необязательны. Имеют смысл для числа. Нарушение даёт error, модуль не продолжит загрузку.

Аргументы

АргументТипОбязательныйПо умолчаниюЧто передавать
schemaтаблицаданетПоля настроек. id модуля подставляется сам, отдельно его писать не нужно.

Что возвращается

Обычная таблица уже выбранных значений, например {max = 100, enabled = true}. Это не объект с методами.

Что происходит после вызова

На сервере читается json. На клиенте файл data не читается, остаются значения по умолчанию. Ошибочный тип останавливает загрузку файла ошибкой invalid config.

Перезагрузка и выгрузка

Функция ничего не вешает в список уборки. После reload файл просто прочитает json снова.

Ограничения

  • Не клади сюда пароль базы. Для базы есть database.json, и его не печатают команды.
  • Неизвестное поле внутри описания, кроме type, default, min и max, код настройки не применяет как-то особо: лишние ключи описания он не читает.

Рядом обычно вызывают

  • Gincy.Config.Register — То же, если id задаёшь сам.

Потолок стамины

local cfg = MOD:Context().Config.Register({
    max = { type = "number", default = 100, min = 10, max = 200 }
})

MOD:Hook("PlayerSpawn", function(ply)
    ply:SetNWInt("Stamina", cfg.max)
end)

Без файла игроки появляются со 100. Если администратор положил в data/gincy/config/stamina.json поле max равное 80, новые спавны получат 80. Значение 0 не пройдёт min, загрузка модуля остановится, старый хук при неудачном reload вернётся вместе со старой загрузкой.
