Ресурс здесь — всё, что переживёт функцию, если его не снять: хук, таймер движка, созданная энтити, сетевой приёмник. ctx:Own сначала включает это, а функцию уборки кладёт в список загрузки. MOD:Hook делает то же самое внутри, поэтому для обычного хука Own не нужен.

Зачем это нужно. Ты создал энтити маркера и хочешь удалить её при перезагрузке модуля. Готового MOD:Marker нет.

Где это встречается на сервере

  • Временный prop на ивент.
  • Свой net.Receive, если ты не пользуешься MOD:Net.

Синтаксис

ctx:Own(function()
    marker = ents.Create("prop_physics")
    marker:SetModel("models/props_junk/wood_crate001a.mdl")
    marker:Spawn()
end, function()
    if IsValid(marker) then marker:Remove() end
end)

Первая функция включает. Вторая убирает. Обе обычные Lua-функции.

Что означает каждая часть

  • apply — Выполнится сразу, если загрузка уже активна. Если модуль ещё только готовится, она выполнится в момент Activate.
  • remove — Выполнится при выгрузке, в обратном порядке относительно других уборок.

Аргументы

АргументТипОбязательныйПо умолчаниюЧто передавать
applyfunctionданетСоздание.
removefunctionданетДолжна терпеть повтор и уже удалённую сущность. Ошибка внутри не останавливает остальные уборки.

Что возвращается

Ничего полезного не возвращает.

Что происходит после вызова

Если ctx.active уже true, включение происходит немедленно, уборка ставится в список. Если модуль ещё в подготовке, пара лежит в очереди до Activate.

Перезагрузка и выгрузка

При Shutdown уборки выполняются с конца списка. Закрытый ctx больше не принимает новые регистрации: вызов упрётся в проверку closed.

Ограничения

  • Не оборачивай MOD:Hook в Own второй раз: хук снимут дважды, это безвредно, но путает.
  • Вторая функция не обязана быть симметричной по строкам, но она обязана существовать. Иначе при перезагрузке объект останется в мире.
  • Вызов на закрытом ctx выдаёт ошибку closed context.

Рядом обычно вызывают

  • MOD:Hook — Хук без Own.
  • ctx:Defer — Только уборка, без шага включения.

Ящик ивента

local ctx = MOD:Context()
local box
ctx:Own(function()
    box = ents.Create("prop_physics")
    box:SetModel("models/props_junk/wood_crate001a.mdl")
    box:SetPos(Vector(0, 0, 0))
    box:Spawn()
end, function()
    if IsValid(box) then box:Remove() end
end)

Пока модуль загружен, на карте стоит ящик. gincy module reload снимет его первой уборкой старой загрузки и, если код создаёт ящик снова, поставит новый. Игроки не останутся с двумя ящиками от двух загрузок.
