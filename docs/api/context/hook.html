Внутри MOD:Hook вызывает именно ctx:Hook. Пиши MOD:Hook, пока не работаешь с ctx напрямую.

Зачем это нужно. Код, который получил ctx из MOD:Context или из окружения загрузчика и вешает событие.

Где это встречается на сервере

  • Приветствие из низкоуровневого файла.

Синтаксис

ctx:Hook("PlayerSpawn", "full", function(ply)
    ply:SetNWInt("Stamina", 100)
end)

Здесь имя хука вторым аргументом обязательно. Короткой формы «только событие и функция» у ctx:Hook нет: её добавляет MOD:Hook.

Что означает каждая часть

  • event — Строка Garry's Mod.
  • id — Твоё имя. Вместе с модулем и номером загрузки оно становится именем hook.Add.
  • fn — Те же аргументы, что у хука движка.

Аргументы

АргументТипОбязательныйПо умолчаниюЧто передавать
eventстрокаданетНапример PlayerSpawn.
idстрокаданетНе функция. Для короткой записи есть MOD:Hook.
fnfunctionданетМожет вернуть значение в игру, если не упала.

Что возвращается

Ничего.

Что происходит после вызова

hook.Add вызывается сразу, если загрузка активна, иначе в Activate. Пока загрузка не активна, обёртка не вызывает твою функцию.

Перезагрузка и выгрузка

hook.Remove по тому же составному имени при Shutdown.

Ограничения

  • Два ctx:Hook с одним id и одним событием делят одно имя и затирают друг друга.

Рядом обычно вызывают

  • MOD:Hook — Короткая форма для обычного кода.

Спавн

ctx:Hook("PlayerSpawn", "stamina", function(ply)
    ply:SetNWInt("Stamina", 100)
end)

Игрок появился, NWInt стал 100. Имя внутри хука содержит номер загрузки, поэтому новая загрузка не снимает чужой аддон.
