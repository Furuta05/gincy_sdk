Повторяющаяся задача с именем, интервалом и числом повторов. Для обычного кода есть MOD:Every.

Зачем это нужно. ctx:Timer нужен, когда ты думаешь категориями timer.Create: имя, задержка, сколько раз. Ноль повторов значит «пока модуль жив», как ноль в timer.Create. Задача всё равно идёт через планировщик Gincy, отдельный timer.Create на неё не создаётся.

Где это встречается на сервере

  • Три напоминания раз в 2 секунды.
  • Постоянный цикл с привычной тройкой чисел.

Синтаксис

ctx:Timer("remind", 2, 3, function()
    print("тик")
end)

Имя, секунды, число запусков, функция.

Что означает каждая часть

  • id — Строка задачи. Повтор с тем же именем заменяет предыдущую.
  • delay — Секунды, не меньше 0.01.
  • repetitions — Целое число, ноль или больше. 0 — без конца. 3 — ровно три вызова.
  • fn — Без аргументов. Вызывается только пока загрузка активна.

Аргументы

АргументТипОбязательныйПо умолчаниюЧто передавать
idстрокаданетИмя внутри модуля.
delayчислоданетМинимум 0.01, иначе ошибка invalid timer.
repetitionsцелоеданет0 значит бесконечно.
fnfunctionданетТело.

Что возвращается

Ничего. Идентификатор задачи наружу не отдаётся, отмена идёт вместе с модулем или заменой по имени.

Что происходит после вызова

Задача создаётся с точностью exact и классом gameplay: бюджет кадра её не откладывает. Источник в диагностике — context.timer.

Перезагрузка и выгрузка

Shutdown отменяет задачу по номеру загрузки. Замена ctx:Timer с тем же именем отменяет старую сразу.

Ограничения

  • Для обхода игроков и spread используй MOD:PlayersEvery.
  • Функция не получает сущность.

Рядом обычно вызывают

  • MOD:Every — Больше форм вызова.

Три гудка

ctx:Timer("horn", 2, 3, function()
    PrintMessage(HUD_PRINTTALK, "старт через несколько секунд")
end)

Сообщение в чат появится три раза с шагом 2 секунды. Четвёртого не будет. Если модуль выгрузить после первого, оставшиеся два не придут.
