Отправляет сообщение и ждёт один ответ по схеме response.

Зачем это нужно. Send ничего не ждёт обратно. Request нужен, когда клиент спрашивает сервер и хочет таблицу в ответ, или наоборот. У канала при регистрации должна быть схема response.

Где это встречается на сервере

  • Клиент спрашивает, можно ли взять навык, и получает причину отказа.
  • Сервер спрашивает клиентский выбор и не хочет держать свой таймер ожидания.

Синтаксис

Gincy.Network.Request(ply, "combat.query", { skill = "fireball" }, function(ok, data)
    if not ok then print("нет ответа") return end
    print(data.allowed)
end, 5)

На клиенте первый аргумент без игрока не используется так же, как у Send: смотри форму Send. В коде Request первый аргумент — peer, на клиенте это может быть nil, дальше id.

Что означает каждая часть

  • peer — Игрок на сервере.
  • id — Канал со схемой response.
  • value — Запрос по основной схеме.
  • callback — Функция результата.
  • timeout — Секунды. По умолчанию 5. Меньше 0,1 поднимается до 0,1, больше 30 режется до 30.

Что возвращается

true и номер запроса, либо false и текст причины. Ответ приходит позже в callback, не как return.

Что происходит после вызова

Запрос встаёт в очередь с отдельным номером. Когда приходит ответ нужной схемы, вызывается callback. Если модуль канала выгрузили раньше, callback получит отмену. По истечении срока ожидание снимается.

Перезагрузка и выгрузка

Выгрузка владельца канала отменяет ждущие запросы.

Ограничения

  • Одновременно ждущих запросов на одного игрока не бесконечно: есть внутренний предел pending.
  • Это не HTTP. Для базы так ждать нельзя.
  • callback обязан существовать даже если тебе всё равно на ответ: иначе это Send.

Рядом обычно вызывают

  • response — Без этого поля Request не живёт.

Можно ли кастовать

Gincy.Network.Register("combat.query", {
    schema = { skill = "string" },
    response = { allowed = "boolean" },
    rate = 4,
    direction = "both",
    handler = function(ply, data)
        local skill = Gincy.Content.Get("combat.skill", data.skill)
        return { allowed = skill ~= nil }
    end
}, "combat")

Gincy.Network.Request(ply, "combat.query", { skill = "fireball" }, function(ok, data)
    if not ok then print("нет ответа") return end
    print(data.allowed)
end, 5)

Обработчик возвращает таблицу по схеме response, не голый true. Её закодируют и отдадут в callback первым аргументом «да, это ответ» и вторым — таблицу. Если вернуть не ту форму, уйдёт текст ошибки, и ok в callback будет ложью. Если за 5 секунд ответа нет, ждать дальше не будут: навык сам не выберется.
