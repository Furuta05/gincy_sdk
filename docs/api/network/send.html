Ставит в очередь уже зарегистрированный канал.

Зачем это нужно. MOD:Send вызывает эту функцию полным именем. На сервере первый аргумент — игрок. На клиенте игрока нет, сообщение идёт на сервер.

Где это встречается на сервере

  • Ответ меню.
  • Рассылка числа одному игроку.

Синтаксис

Gincy.Network.Send(ply, "combat.select_skill", { skill = "fireball" })

Сервер. На клиенте: Gincy.Network.Send("combat.select_skill", { skill = "fireball" }).

Что означает каждая часть

  • ply — Только на сервере. Невалидный игрок — отказ.
  • id — Полное имя канала.
  • value — Таблица по схеме.
  • options — Необязательная таблица. coalesceKey заменяет ещё не ушедшее сообщение с тем же ключом.

Аргументы

АргументТипОбязательныйПо умолчаниюЧто передавать
ply, idсм. формыданетПутаница аргументов на сервере и клиенте — частая ошибка: на сервере без игрока канал прочитается как игрок.
valueтаблицаданетДолжно пройти Encode по схеме.

Что возвращается

true, если встало в очередь. false и ошибка: нет канала, неверное направление, слишком большой пакет, бюджет модуля или очередь.

Что происходит после вызова

Данные кодируются и ждут ближайшей отправки кадра. Успех постановки в очередь ещё не значит, что клиент уже показал меню.

Перезагрузка и выгрузка

Снятый канал вычищается из очереди. Игрок, который вышел, в отправку не попадёт.

Ограничения

  • Фоновые сообщения могут быть выброшены, если очередь полная.
  • Лимит скорости отправителя общий на модуль-владельца канала.

Рядом обычно вызывают

  • MOD:Send — Короткое имя.
  • Register — Сначала канал.

Ответ

Gincy.Network.Send(ply, "combat.select_skill", { skill = "fireball" })

Если канал combat.select_skill объявлен в обе стороны и поле skill строка, таблица встанет в очередь этому игроку. Лишнее поле вернёт GINCY-NET-PAYLOAD или ошибку схемы и в очередь не попадёт.
