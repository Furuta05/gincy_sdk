Выключает хуки, задачи, сеть и контент текущей загрузки модуля прямо из Lua.

Зачем это нужно. Обычно модуль выключают командой gincy module disable. Unload нужен, если это решение принимает сам код, например тестовый модуль доиграл сценарий.

Где это встречается на сервере

  • Тестовый модуль, который должен исчезнуть после проверки.
  • Временная ивентовая система внутри одного рестарта.

Синтаксис

MOD:Unload()

Аргументов нет.

Что означает каждая часть

  • MOD — Объект той загрузки, которую надо закрыть.

Что возвращается

true.

Что происходит после вызова

Закрывается контекст: уборки с конца, отмена задач этого номера, снятие сети этого номера. Затем отпускается контент владельца и регистрация его хранилищ. Состояние модуля становится DISABLED. Запись остаётся в списке, но хуки уже не живые.

Перезагрузка и выгрузка

Повторный Unload по уже закрытому контексту не вешает хуки обратно. Новые MOD:Hook после закрытия не регистрируются: контекст закрыт.

Ограничения

  • Не удаляет .gmod и папку.
  • Не удаляет строки PostgreSQL.
  • Не выключает каскадом другие модули, которые от него зависели. Для этого есть команда disable --cascade.

Рядом обычно вызывают

  • reload — Перечитать файлы, а не просто выключить.
  • Disable — Команда загрузчика.

Конец теста

local MOD = Gincy.Module("test")
MOD:Hook("PlayerSpawn", function(ply) end)
MOD:After(1, function() end)
MOD:Every(5, function() end)
MOD:Unload()

Сразу после Unload хук спавна, одноразовый After и повтор каждые 5 секунд этому модулю больше не принадлежат. Если секунда ещё не прошла, After не выстрелит.
