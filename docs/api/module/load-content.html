MOD:LoadContent

Включает одну запись контента из таблицы, без файла на диске.

Обычно записи приходят из папки. LoadContent нужен, когда модуль сам собрал таблицу в коде и хочет прогнать её через ту же проверку, что и файл.

Зачем это нужно. Навык, собранный из данных базы. Предмет, выданный событием на одну сессию.

Где это встречается на сервере

  • Сервер события создаёт временный бафф как запись контента.
  • Тест в коде модуля без lua-файла в gincy_content.

Синтаксис

MOD:LoadContent("skill", "fireball", {
    name = "Fireball",
    damage = 50,
    cooldown = 4
})

Тип можно передать коротко: skill станет combat.skill.

Что означает каждая часть

  • тип — Короткое или полное имя уже объявленного MOD:Content.
  • id — Идентификатор записи, как имя файла.
  • таблица — Те же поля, что в файле. Функции поведения можно положить сюда же.
  • info — Необязательная таблица. Модуль сам допишет владельца и номер своей загрузки.

Что возвращается

true и экземпляр, если запись принята. false и ошибка, если тип чужой, поля плохие или зависимость отсутствует. При неудачной замене уже живой записи старая не удаляется.

Что происходит после вызова

Идёт тот же путь, что у файла: проверка, зависимости, подготовка, затем запись. Успех отменяет задачи предыдущего экземпляра этого id.

Перезагрузка и выгрузка

Выгрузка модуля отпускает экземпляры этого владельца.

Ограничения

  • Тип надо объявить раньше через MOD:Content.
  • Чужой префикс типа не принимается.
  • Это не запись файла на диск.

Рядом обычно вызывают

  • MOD:Content — Сначала тип.
  • Call — Потом вызвать cast.

Временный бафф

MOD:Content("buff", { name = "string", power = "number" })

MOD:LoadContent("buff", "rally", {
    name = "Rally",
    power = 10
})

Запись rally появляется сразу, файла в gincy_content нет. Если power передать строкой, вызов вернёт неудачу, и старой записи, если она была, это не сотрёт.
