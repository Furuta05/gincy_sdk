MOD:Net описывает, какие поля можно прислать. Это замена ручным net.WriteString и net.ReadString: чужой тип отсекается до твоей игровой функции.

Зачем это нужно. Игрок выбрал навык, нажал кнопку в меню, отправил строку чат-команды, которую нельзя принять вслепую.

Где это встречается на сервере

  • Выбор навыка в меню.
  • Покупка предмета по строковому id.
  • Запрос синхронизации, где в ответе тоже таблица.

Синтаксис

MOD:Net("select_skill", {
    skill = "string"
})

Имя без точки. На проводе оно станет idМодуля.select_skill. Таблица — поля и их типы строками.

Что означает каждая часть

  • select_skill — Короткое имя. Полное имя собирается само.
  • skill = "string" — Поле skill должно быть строкой. Другие типы схемы: number, integer, boolean. Вопросительный знак на конце, например "number?", делает поле необязательным.
  • таблица — Это не вызов net.Start. Это описание.

Аргументы

АргументТипОбязательныйПо умолчаниюЧто передавать
nameстрокаданетКороткое имя сообщения.
schemaтаблицаданетПары поле = тип. Лишние ключи в присланных данных потом отвергаются.

Что возвращается

Строка полного имени, например stamina.select_skill. Её же ждёт низкоуровневая отправка, но MOD:Send принимает короткое имя.

Что происходит после вызова

Сообщение регистрируется в обе стороны, лимит 8 сообщений в секунду. Обработчик внутри проверяет поля и, если записан MOD:Receive, вызывает его с игроком и уже проверенной таблицей. Кривые данные не вызывают Receive и пишутся как GINCY-NET-SCHEMA.

Перезагрузка и выгрузка

При выгрузке модуля регистрация этого поколения снимается. Старый Receive больше не вызывается.

Ограничения

  • Нужно разрешение network.register. У простого Gincy.Module оно уже есть. У модуля из manifest его надо вписать в capabilities, иначе ctx:Require внутри регистрации остановит загрузку.
  • Имя полного канала не длиннее правил идентификатора.
  • Поля задаются здесь, а игровая реакция — в Receive. Одно без другого: Net без Receive просто проверит пакет и ничего не сделает.

Рядом обычно вызывают

  • MOD:Receive — Что выполнить на сервере.
  • MOD:Send — Послать таблицу игроку.
  • Schema — Какие типы вообще есть.

Выбор навыка

local MOD = Gincy.Module("combat")

MOD:Net("select_skill", {
    skill = "string"
})

MOD:Receive("select_skill", function(ply, data)
    print(ply:Nick() .. " выбрал " .. data.skill)
end)

Клиент пришлёт таблицу с полем skill. Если придёт число или лишнее поле, print не выполнится. Если придёт строка, в консоли сервера будет ник и имя навыка. Канал называется combat.select_skill.
