Gincy.Module("имя") возвращает объект модуля. Дальше почти весь обычный код идёт через него: MOD:Hook, MOD:Every, MOD:Net, MOD:Content.

Зачем это нужно. Один объект помнит, что создано этим модулем. Когда модуль выгружают, Gincy снимает именно его хуки и задачи, а не все хуки сервера.

Где это встречается на сервере

  • Система выносливости.
  • Боевая система, которая потом объявит тип навыка.
  • Маленький тестовый модуль в одном файле.

Синтаксис

local MOD = Gincy.Module("stamina")

Имя в кавычках обязано совпасть с id в manifest.lua, если файл выполняется во время загрузки этого модуля.

Что означает каждая часть

  • Gincy — Таблица каркаса. Она уже есть, когда выполняется файл модуля.
  • Module — Функция, не метод. Точка, не двоеточие: Gincy.Module, а не Gincy:Module.
  • "stamina" — id. Первая буква латинская строчная, дальше строчные буквы, цифры и подчёркивание. Точка и дефис нельзя.
  • MOD — Обычная локальная переменная. Имя можешь выбрать сам, на работу это не влияет.

Аргументы

АргументТипОбязательныйПо умолчаниюЧто передавать
idстрокаданетТот же идентификатор, что в manifest. Внутри загрузки модуля чужое имя вызывает ошибку «привязан к текущему id». Вне загрузки, если контекста ещё нет, создаётся простой модуль с версией 1.0.0 и разрешениями на сеть, контент и чтение/запись базы.

Что возвращается

Возвращается объект с методами Hook, On, After, Every, PlayersEvery, Net, Receive, Send, Content, LoadContent, Storage, Unload, Context. Его можно сохранить в local MOD.

Что происходит после вызова

Если модуль уже загружается, возвращается обёртка над его текущей загрузкой, новая загрузка не создаётся. Если ты вызвал функцию сам, вне загрузчика, и модуль ещё не занят, создаётся активная загрузка и модуль помечается ACTIVE.

Перезагрузка и выгрузка

При выгрузке модуля или при его горячей перезагрузке задача, хук или регистрация этой загрузки снимается. Следующий запуск файла создаёт новые. Старая функция больше не вызывается. MOD:Unload делает это сразу из кода.

Ограничения

  • Повторный вызов с тем же id во время той же загрузки возвращает новый объект-обёртку, но хуки остаются на той же загрузке.
  • Простой модуль, созданный вне manifest, не получает горячую перезагрузку из папки сам по себе: его не из чего перечитывать.

Рядом обычно вызывают

  • MOD:Hook — Событие игрока.
  • MOD:Every — Повтор по времени.
  • manifest — Откуда берётся id.

Стамина

local MOD = Gincy.Module("stamina")

MOD:Hook("PlayerSpawn", function(ply)
    ply:SetNWInt("Stamina", 100)
end)

MOD — объект модуля stamina. PlayerSpawn — событие Garry's Mod, оно срабатывает, когда игрок появляется. Внутри обычный GLua. Gincy запоминает хук за stamina. После reload stamina старая функция на спавне уже не стоит, новая из файла встанет заново.
