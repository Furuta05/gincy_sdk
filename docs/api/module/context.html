Context, коротко ctx, — это одна конкретная загрузка модуля. Она помнит список того, что надо убрать. MOD:Hook и MOD:Every пользуются ей сами. MOD:Context() нужен, когда ты регистрируешь команду, поток или свою уборку.

Зачем это нужно. Своя консольная команда модуля. Свой ресурс, которого нет среди готовых методов.

Где это встречается на сервере

  • Открыть ctx.Console.
  • Вызвать ctx:Own для временной сущности.

Синтаксис

local ctx = MOD:Context()

Дальше методы пишутся как ctx:Own, ctx.Network:Register.

Что означает каждая часть

  • ctx — Таблица загрузки. Поля ID и generation — идентификатор модуля и номер этой загрузки. Номер растёт, чтобы старая уборка не сняла уже новые регистрации.

Что возвращается

Таблица ctx. Не копируй её в глобальную переменную навсегда: после перезагрузки это будет уже закрытый объект.

Что происходит после вызова

Ничего не регистрирует. Только возвращает то, что и так держит MOD.

Перезагрузка и выгрузка

После Shutdown тот же объект помечен закрытым. Новый код модуля получит новый ctx через новый MOD:Context().

Ограничения

  • Для хука, таймера, сети MOD:Net и контента MOD:Content лезть сюда не нужно.
  • Поле generation не надо сохранять в файл контента.

Рядом обычно вызывают

  • ctx:Own — Своя уборка.
  • Команда модуля — Своя подкоманда gincy.

Когда MOD мало

local ctx = MOD:Context()
ctx.Console:Register({
    description = "Стамина",
    subcommands = {
        { name = "get", description = "Показать", handler = function(ply)
            print("команда модуля")
        end }
    }
})

Команда встанет под именем модуля. При выгрузке регистрация команды снимается. Описание полей команды — на странице ctx.Console.
