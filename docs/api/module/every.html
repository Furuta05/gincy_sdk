MOD:Every

Повторяет функцию через заданные секунды. Может быть с именем, с настройками и с привязкой к игроку или сущности.

MOD:Every заменяет связку timer.Create плюс ручная проверка «игрок ещё на сервере?». Все такие задачи лежат в одном планировщике. Он не бежит по всему списку каждый тик: смотрит только те, чей срок уже наступил.

Зачем это нужно. Реген, голод, проверка зоны, бафф на конкретном игроке, уборка раз в полминуты.

Где это встречается на сервере

  • Раз в секунду пройти живых игроков.
  • Раз в секунду лечить одного игрока, пока он на сервере.
  • Раз в 30 секунд уборка, которой можно чуть опоздать.

Синтаксис

MOD:Every(1, function()
    for _, ply in ipairs(player.GetAll()) do
        if not IsValid(ply) then continue end
        -- общая работа
    end
end)

Форма 1: число и функция. Имени нет. Точность normal.

MOD:Every("stamina_regen", 1, function()
    for _, ply in ipairs(player.GetAll()) do
        local value = ply:GetNWInt("Stamina", 0)
        if value < 100 then ply:SetNWInt("Stamina", math.min(100, value + 1)) end
    end
end)

Форма 2: имя, число, функция. Повторный вызов с тем же именем заменяет старую задачу.

MOD:Every("cleanup", 30, { precision = "relaxed", class = "maintenance" }, function()
    -- уборка кэша
end)

Форма 3: имя, число, таблица настроек, функция.

MOD:Every(ply, "regen", 1, function(target)
    if target:GetNWInt("Stamina", 0) < 100 then
        target:SetNWInt("Stamina", target:GetNWInt("Stamina", 0) + 1)
    end
end)

Форма 4: сущность или игрок, имя, число, функция. Функция получит эту сущность. Если она стала невалидной, задача снимается.

MOD:Every(ply, "regen", 1, { precision = "exact" }, function(target) end)

Форма 5: то же плюс таблица настроек перед функцией.

Что означает каждая часть

  • MOD — Объект модуля.
  • :Every — Метод. Двоеточие обязательно в вызове.
  • interval — Секунды между запусками. Число, ноль или больше.
  • name — Строка. Необязательна только в самой короткой форме. С именем новая задача с тем же именем в этом модуле отменяет предыдущую.
  • entity — Необязательный первый аргумент, если дальше строка-имя. Это не список игроков.
  • opts — Необязательная таблица перед функцией.
  • fn — Последний аргумент всегда она. Для формы с сущностью получит эту сущность. Иначе аргументов нет.
  • квадратные скобки — В тексте документации они значат «можно не писать». В код их копировать не нужно.

Что возвращается

Строка-идентификатор задачи. Её понимает Gincy.Scheduler.Cancel и команда gincy scheduler inspect, если передать имя.

Что происходит после вызова

Задача встаёт в кучу по времени следующего запуска. На каждом тике планировщик достаёт только тех, чей срок наступил. Ошибка печатается не каждый тик, а первый раз и дальше реже, и после 8 подряд задача отключается. Медленный вызов копится в счётчиках, их показывает gincy scheduler.

Перезагрузка и выгрузка

При выгрузке модуля или при его горячей перезагрузке задача, хук или регистрация этой загрузки снимается. Следующий запуск файла создаёт новые. Старая функция больше не вызывается. Выход игрока снимает задачи, привязанные к нему, не дожидаясь unload модуля. Невалидная сущность — тоже.

Ограничения

  • Не создавай timer.Create внутри callback «на всякий случай»: для периода хватает Every.
  • Обход всех игроков внутри Every(1) — нормально для редкой работы. Для частого обхода всех живых есть PlayersEvery.
  • Имя задачи уникально внутри модуля, не на всём сервере.
  • Короткая форма без имени не заменяет предыдущую короткую форму. Они копятся, пока модуль жив.

Рядом обычно вызывают

  • PlayersEvery — Один обход всех игроков.
  • After — Один раз.
  • gincy scheduler — Посмотреть, кто медленный.

Реген всех

MOD:Every("stamina_regen", 1, function()
    for _, ply in ipairs(player.GetAll()) do
        local value = ply:GetNWInt("Stamina", 0)
        if value < 100 then
            ply:SetNWInt("Stamina", math.min(100, value + 1))
        end
    end
end)

Раз в секунду планировщик вызывает эту функцию. Внутри обычный цикл по игрокам. Имя stamina_regen нужно, чтобы повторная загрузка кода заменила задачу, а не добавила вторую. При unload модуля цикл прекращается.

Реген одного

hook.Add -- не нужен
MOD:Hook("PlayerSpawn", function(ply)
    MOD:Every(ply, "regen", 1, function(target)
        local value = target:GetNWInt("Stamina", 0)
        if value < 100 then target:SetNWInt("Stamina", value + 1) end
    end)
end)

На спавне у этого игрока появляется именная задача. Функция получает его как target. Проверять IsValid и делать timer.Remove не нужно: при выходе задача снимается сама. Имя regen одно на модуль, поэтому новый спавн другого игрока заменит задачу предыдущего. Если реген нужен каждому одновременно, имя должно включать SteamID, либо используй PlayersEvery.
